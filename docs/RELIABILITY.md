# 可靠性与异常处理

目标是降低漏用卡片的概率，并对无法确认的操作保留恢复路径。应用不承诺一定能使用每张卡。

| 场景 | 处理 |
| --- | --- |
| 使用响应丢失 | 保留请求标识，下一轮或重启后用同一标识确认 |
| 卡片从列表消失 / 已到期 | 待确认请求仍能确认，不仅遍历当前可用列表 |
| 使用成功但刷新失败 | 成功记录和通知 outbox 保留，不再次使用同一卡 |
| 无可重置额度 | 继续尝试，不把 `nothingToReset` 当成成功 |
| 单卡请求失败 | 记录异常，继续考虑其他临近到期卡 |
| 存储写入失败 | 不发送未记录的使用请求 |
| 记录损坏或账号标识缺失 | 暂停自动使用并提示，不清空重建记录 |
| 卡片明细暂缺 / 被截断 | 保留已知到期时间，继续查询完整情况 |
| 通知权限关闭 / 提交失败 | 不记成已提醒，显示异常状态 |
| 系统待提醒任务缺失 | 读取系统任务后重新安排 |
| 断网或系统唤醒 | 加快失败后的检查，并在恢复后补查 |
| 重复应用副本 | 文件锁允许一个监控实例运行 |

自动使用默认提前 60 分钟。检查频率为常态 60 秒、最后 1 小时 15 秒、最后 2 分钟或未确认请求 5 秒；单次 RPC 最多等待 12 秒，处理时不会并发开启另一轮。

提醒阶段为到期前 24 小时、1 小时、10 分钟、2 分钟。未来提醒交由系统管理，成功使用后的未来提醒会取消。通知提交成功不等于用户看到通知，专注模式和系统显示策略仍可能影响提示。

阻止 App Nap 以维持监控；临近到期且自动使用开启时阻止空闲睡眠。合盖、主动睡眠、关机和应用不运行期间不能消费卡片。登录启动不是崩溃重启守护。

## 已验证与未验证

已验证的模拟场景见 `tests/MonitorTests.swift`；RPC 真实子进程夹具见 `tests/test_rpc.py`。实际账号只读查询和通知授权/待提醒检查已执行。没有用真实卡片验证消费成功，也未做合盖、断电或长时间断网的真实设备实验。

历史检查结果保存在 [reliability-audit.txt](reliability-audit.txt)，其断言数和运行数据是当时的记录，当前行为以源码和 `make test` 为准。
